# 心屿部署指南

本指南以仓库现有的 Flask + SQLite 应用为准。实际用户入口是 `/web/`，管理入口是 `/admin`；根路径 `/` 不是项目主页。首次公开部署前，请先设置独立的管理员密码和 Flask 密钥。

## 1. 环境与目录

- Python 3.12（与项目 README 保持一致）；建议使用独立虚拟环境。
- Linux 服务器建议 Ubuntu 22.04/24.04、Nginx、HTTPS 域名；本地体验只需要 Python。
- 应用数据库位于 `backend/emotion.db`，上传文件位于 `backend/uploads/`，APK 文件位于 `backend/apk/`。这些运行数据应在升级前备份。

```text
浏览器 → HTTPS / Nginx → 127.0.0.1:5000 / Gunicorn → Flask → SQLite
```

## 2. 本地启动

在仓库根目录运行以下命令。Windows PowerShell 使用第一组，Linux/macOS 使用第二组。

```powershell
cd backend
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
Copy-Item .env.example .env
# 编辑 .env：填入 MIMO_API_KEY、至少 32 位随机 SECRET_KEY、独立 ADMIN_PASSWORD
.\.venv\Scripts\python.exe app.py
```

```bash
cd backend
python3.12 -m venv .venv
. .venv/bin/activate
python -m pip install -r requirements.txt
cp .env.example .env
# 编辑 .env：替换示例密钥和默认管理员密码
python app.py
```

打开 `http://127.0.0.1:5000/web/`。管理页面在 `http://127.0.0.1:5000/admin`。AI 对话需要有效的 `MIMO_API_KEY`；未配置时仍可检查其他非 AI 页面。

> `python app.py` 使用 Flask 调试服务器（源码中设置了 `debug=True`），只用于本机开发，不要直接对公网开放。

## 3. Linux 服务器部署

```bash
sudo apt update
sudo apt install -y python3.12 python3.12-venv nginx
git clone https://github.com/1828703450qqcom-ux/xinyu.git /opt/xinyu
cd /opt/xinyu/backend
python3.12 -m venv .venv
. .venv/bin/activate
python -m pip install -r requirements.txt gunicorn
cp .env.example .env
chmod 600 .env
# 编辑 .env，替换全部示例值
gunicorn --workers 2 --bind 127.0.0.1:5000 app:app
```

确认 `http://127.0.0.1:5000/web/` 能打开后，按下面的示例添加 systemd 服务。将 `User` 与 `Group` 改为实际运行用户，确保该用户对 `backend/` 中数据库与上传目录有写权限。

```ini
# /etc/systemd/system/xinyu.service
[Unit]
Description=Xinyu Flask service
After=network.target

[Service]
User=www-data
Group=www-data
WorkingDirectory=/opt/xinyu/backend
ExecStart=/opt/xinyu/backend/.venv/bin/gunicorn --workers 2 --bind 127.0.0.1:5000 app:app
Restart=always

[Install]
WantedBy=multi-user.target
```

```bash
sudo chown -R www-data:www-data /opt/xinyu/backend
sudo systemctl daemon-reload
sudo systemctl enable --now xinyu
sudo systemctl status xinyu
```

Nginx 可先代理到本机服务，再按域名配置可信证书。下面把 `/` 重定向到实际入口 `/web/`。

```nginx
server {
    listen 80;
    server_name example.com;
    client_max_body_size 50m;
    location = / { return 302 /web/; }
    location / {
        proxy_pass http://127.0.0.1:5000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

部署后配置 HTTPS，并只对外开放 80/443。不要把 5000 端口开放到公网。

## 4. 验收、备份与更新

```bash
curl -I http://127.0.0.1:5000/web/
curl -I http://127.0.0.1:5000/admin
journalctl -u xinyu -n 100 --no-pager
```

备份前先停止写入或短暂停服务，复制 `backend/emotion.db`、`backend/uploads/`、`backend/apk/` 及服务器上的 `.env` 到受控位置。更新流程是备份 → `git pull` → 虚拟环境内 `pip install -r requirements.txt` → `systemctl restart xinyu` → 检查 `/web/` 与日志。`backend/.env`、数据库和用户上传文件不要提交到公开仓库。

## 5. 常见问题

| 现象 | 检查项 |
|---|---|
| 根路径 404 | 访问 `/web/`；按上面的 Nginx 示例添加根路径跳转。 |
| AI 对话失败 | 检查 `backend/.env` 中的 `MIMO_API_KEY`、模型服务网络和日志。 |
| 数据库只读 | 检查 systemd 运行用户对 `backend/emotion.db` 及其父目录的写权限。 |
| 管理员无法登录 | 检查 `ADMIN_PASSWORD` 是否仍为示例值、服务是否已重启。 |

本项目涉及心理健康信息。正式上线前，应补齐隐私告知、数据保留/删除策略和权限审计；AI 回复仅作辅助，不应替代专业诊疗。
